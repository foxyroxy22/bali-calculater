# 발리 경비 계산기 & 가계부 — 설계 문서

## 1. 개요

발리 여행 중 식당/쇼핑 계산서를 세금·서비스차지 구조에 맞춰 계산하고, 계산 결과를 가계부로 저장해 친구와 공유(캡처 전달)하는 정적 웹앱. 사용자는 본인 + 친구 1명(총 2인), 로그인/서버 없음.

## 2. 스택

- 순수 HTML/CSS/JS (프레임워크 없음)
- 데이터 저장: 브라우저 `localStorage`
- 배포: GitHub Pages (정적 호스팅)
- PWA 미적용 — iOS Safari "홈 화면에 추가" 기본 기능만으로 충분

## 3. 화면 구조

### 3.1 상단 탭 (같이 / 개인)

- 두 개의 최상위 탭, 각각 독립적인 계산기 상태 + 독립적인 "마지막 입력 환율" 값을 가짐
- 탭 전환 시 계산기 입력값(메뉴 리스트, 세금모드, %)은 초기화됨
- 가계부 리스트는 현재 선택된 탭의 `tab_type` 값으로 필터링
- 계정 구분 없음 — 같은 기기에서 두 탭 모두 누구나 열람 가능

### 3.2 계산기 뷰

- 세금 모드 3단 토글: `none`(가격만) / `plus`(세금만) / `plusplus`(세금+서비스차지)
  - `none`: 추가요금 0%
  - `plus`: 세금(%)만 적용, 서비스차지 입력 비활성화
  - `plusplus`: 세금(%) + 서비스차지(%) 둘 다 적용
- 세금/서비스차지 % 입력: 기본값 각 10%, 마지막 입력값을 localStorage에 기억해 다음 접속 시 프리셋으로 사용
- 메뉴 항목: 이름 + 가격(Rp) 행 추가/삭제, 개수 제한 없음 — 목록이 길어지면 해당 영역만 스크롤
- 실시간 계산 표시: 소계(Rp) → 추가요금(Rp) → 총액(Rp) → 총액(원화)
- 환율 입력: "100루피아 = ___원" 고정 포맷
  - 탭(같이/개인)마다 별도로 마지막 입력값을 localStorage에 저장 — 같이 탭과 개인 탭의 기본 환율이 서로 다르게 유지됨
  - 언제든 수동 수정 가능
- "저장하기" 버튼 → 가계부에 항목 기록 후 가계부 뷰로 이동(또는 리스트 최상단에 추가)

### 3.3 가계부 뷰

- 리스트형, 날짜 최신순 기본 정렬
- 항목 클릭 → 상세 펼치기(메뉴 리스트, 세금모드/%, 계산 내역, 적용 환율)
- 항목별 수정/삭제
- **환율 수정**: 상세 펼침 상태에서 해당 항목의 `fx_rate_snapshot`을 개별적으로 수정할 수 있는 필드 제공 (트래블월렛 재충전으로 과거 환율이 달랐던 걸 나중에 인지했을 때 보정하는 용도). 수정 시 해당 항목의 `total_krw`도 재계산.
- 상단 요약: 현재 탭 기준 총액(Rp + 원화)
- 필터: 날짜 범위

### 3.4 데이터 내보내기

- "내보내기" 버튼 → 전체 `entries` 배열을 JSON 파일로 다운로드
- 용도: 여행 종료 후 파일을 Claude에게 전달해 Notion 등에 기록시키기 위함 → 가공 없이 기획서에 정의된 필드 그대로, 사람이 읽기 쉬운 들여쓰기(pretty-printed) JSON으로 저장

## 4. 데이터 구조

```json
{
  "entries": [
    {
      "id": "string (uuid)",
      "tab_type": "shared | personal",
      "date": "ISO 8601 string, 수동 수정 가능",
      "items": [{ "name": "string", "price_idr": "number" }],
      "tax_mode": "none | plus | plusplus",
      "tax_rate": "number (%)",
      "service_rate": "number (%)",
      "subtotal_idr": "number",
      "extra_idr": "number",
      "total_idr": "number",
      "fx_rate_snapshot": "number (100 IDR = ? KRW, 저장 시점 고정, 이후 수정 가능)",
      "total_krw": "number",
      "memo": "string, optional"
    }
  ]
}
```

localStorage 키 구성:
- `bali_expense_entries`: 위 entries 배열
- `bali_expense_last_rate_shared`: 같이 탭 마지막 입력 환율
- `bali_expense_last_rate_personal`: 개인 탭 마지막 입력 환율
- `bali_expense_last_tax_rate`, `bali_expense_last_service_rate`: 마지막 입력 세금/서비스차지 %

## 5. 디자인 시스템 적용

Baemin 디자인 참조(`DESIGN.md`)에서 실용적으로 발췌 적용:
- 포인트 컬러: 민트 `#0cefd3` (주요 액션 버튼, 활성 탭 표시, 강조 텍스트)
- 배경/서페이스: `#ffffff` 캔버스, `#f6f6f6` 패널
- 텍스트: `#222222` 기본, `#6c6d6f` 보조
- 라운드: 카드/버튼 12px, 작은 컨트롤 8px
- 버튼 스타일: Baemin 다운로드카드 패턴 참고 (흰 배경 + 그림자 없는 플랫 필, 12px 라운드) — 1차 액션(저장하기)은 민트 채움, 보조 액션은 아웃라인/뉴트럴
- 타이포: 시스템 폰트 스택 사용 (WORK 폰트는 실제 로드 가능한 웹폰트 아님 — Baemin 웹 실측 기준 시스템 폰트로 대체)
- 레이아웃 여백: 8/12/16/20/24/32px 스케일 사용

## 6. 에러 처리

- 가격/환율/% 입력: 숫자가 아니거나 음수면 저장/계산 시 입력 무시(0 처리) 및 해당 필드 시각적 경고 표시. 별도 모달/토스트 불필요.
- localStorage 읽기 실패(손상된 JSON): 빈 배열로 폴백, 콘솔에 에러만 기록. 사용자 데이터 2인 규모라 복구 UI는 만들지 않음.
- 메뉴 항목 0개 상태에서 저장 시도: 저장 버튼 비활성화.

## 7. 테스트 방침

- 백엔드 없는 정적 앱이므로 자동화 테스트는 핵심 계산 로직(세금모드별 총액 계산, 환율 변환, KRW 환산)에 대한 순수 함수 단위 테스트만 작성
- UI는 브라우저에서 수동 확인 (골든 패스: 계산 → 저장 → 가계부 확인 → 수정 → 내보내기)
